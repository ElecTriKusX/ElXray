# Проверка безопасности дополнений Electrium

Это проверка изменённых путей и регрессий, не полный аудит Xray, ОС или зависимостей. Текущая стадия: rate policy + локальное runtime управление. Device proof, WebRTC, TUN клиента, агент и UI панели ещё не реализованы.

## Модель доверия

UUID аутентифицирует пользователя VLESS. Для бюджетов используется назначенный сервером email; HTTP-заголовок, переданный клиентом email или source IP не назначают тариф. Несколько email одной подписки разделяют бюджет. Общий UUID не является доказательством физического устройства или официального приложения.

Административный JSON и локальный API доверенные. Удалённый VPN-клиент не должен иметь к ним доступ. Внешний backend управляет через отдельного аутентифицированного агента; стандартный Commander не аутентифицирует локальные процессы.

## Закрытые регрессии

| Проблема | Исправление/проверка |
|---|---|
| Вариант регистра email обходил привязку | Нормализация по правилам VLESS/Trojan; дубликаты отклоняются, включая unlimited |
| Stats-wrapper скрывал raw-copy guard | SizeStatWriter передаёт RequiresBufferedCopy; proxy-тест проходит с вложенной статистикой |
| Nil-сентинел/большой stream-буфер попадал downstream некорректно | Chunker пропускает nil, сохраняет bytes, делит stream, сохраняет UDP границы; fuzz/property seeds |
| Ограничитель мог удержать буферы/ожидания при остановке | Отмена контекста/Interrupt/Close, освобождение pending, EOF после полного drain, stress |
| Unlimited соединение могло остаться вне последующей runtime политики | Все управляемые направления обёрнуты, включая 0; guard запрещает splice с момента открытия |
| Смена скорости оставляла старые долгие reservations или создавала новый burst | Стабильный bucket, без будущих reservations; update будит waiters, сохраняет credit, up/down меняются под одним lock |
| Устаревший/частичный admin update снимал лимит | CAS revision, точный retry, обязательная presence обоих rates/disabled, last-known-good при ошибке |
| Пропущенный email превращал тариф в unlimited | Опциональный requireSubscription=true; пустой email аутентифицированного пользователя тоже блокируется |
| Случайно опубликованный SubscriptionService | JSON требует literal loopback/Unix listen; RPC дополнительно проверяет local peer |
| Гонка фонового TLS certificate reload и handshake | Live store под RWMutex, новый объект при reload/OCSP, уже выбранный сертификат не меняется; публичный BuildCertificates возвращает snapshot |

TLS-гонка обнаружена новым Vision `-race` сценарием в исходном пути TLS, не в счётчике скорости. Добавлен отдельный TestCertificateReloadConcurrentSelection: параллельный выбор сертификата во время загрузки новой пары с диска. Наличие гонки было воспроизведено до исправления. Полное семейство механизмов TLS/OCSP не аудировалось; исходный lifecycle фоновых reload goroutines этим патчем не переделывался.

## Автоматическая проверка

- Общий TCP бюджет, независимые направления/аккаунты/экземпляры, invalid config и case matching.
- Отмена ожидающей записи, освобождение управляемых буферов, nil/EOF/UDP границы и короткий fuzz chunker.
- Manager CAS, конфликт двух конкурентных обновлений, detached snapshots, retry без reset, восстановление revision/disabled, запрет unmanaged.
- Реальный локальный gRPC: Get/Set, conflict/retry, omitted fields, отказ remote/missing peer.
- Реальный VLESS TCP, неверный UUID, TCP mux, UDP, UDP mux и XUDP с двумя потоками.
- Vision TLS и REALITY с локальным TLS target, внутренний TLS 1.3 stream, включение лимита на действующих unlimited потоках.
- Python HTTP fixture и runner, отсутствие SOCKS/direct fallback в TUN-режиме, обработка counters/reset.
- Собранный бинарник: три процесса, одновременные download/upload, CLI API, смена скоростей, retry/conflict, disabled, unlimited и уборка только собственных процессов.

Команды и актуальный протокол запуска — [ACCEPTANCE_TESTS.md](ACCEPTANCE_TESTS.md), результаты — [VALIDATION.md](VALIDATION.md). Linux-проверки не заменяют Windows/macOS и физический стенд. Полный пакет transport/internet/tls включает внешние ECH/DNS тесты: в этой среде они не проходят из-за недоступного внешнего DNS/сайта. Используется отдельный локальный regression test; общий TLS suite не объявляется успешным. `go vet ./infra/conf` также имеет исходный unreachable legacy reverse-код; выбранные остальные пакеты проверяются отдельно.

## Ограничения перед эксплуатацией

- Без requireSubscription=true неизвестный email сохраняет upstream-поведение. Новые email/пользователи через штатный API не получают политику автоматически; текущие привязки изменяются стартовым JSON и рестартом.
- Runtime состояние в памяти. Панель/агент обязаны сохранять desired/applied policy и генерировать стартовый JSON до допуска пользователей; ядро не переписывает БД/конфиг панели.
- disabled блокирует полезные операции и будит waiters, но не обещает моментальное закрытие каждого idle socket. Это не отзыв device key/UUID. Ранее отправленные байты могут дойти после update.
- Не ограничены handshake CPU, количество соединений, число физических устройств и память всего аккаунта. Равные доли между потоками не гарантируются. Timer contention/CPU при большом количестве потоков требуют длительной нагрузки.
- UDP pacing не гарантирует жёсткий короткий потолок для целых крупных датаграмм. Потери, jitter, очереди и MTU проверяются отдельно.
- Управляемые unlimited потоки остаются буферными; производительность может отличаться от stock splice. Любая новая wrapper/raw-copy цепочка должна сохранять guard.
- Считаются полезные байты, а не wire bytes. Внешний WebRTC адаптер обязан проводить авторизованные данные через тот же серверный budget; иначе политика ядра его не ограничит.
- Между нодами бюджет не синхронизируется — это согласованная граница проекта. Глобальный допуск устройств проектируется отдельно.
- Не завершены физические LAN/TUN тесты, длительные CPU/RSS/FD замеры и проверка реального клиента. До них production-ready статус не присваивается.
