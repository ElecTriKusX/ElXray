# Ограничение скорости подписки на ноде

Расширение нашего форка; штатные конфигурации upstream не предоставляют эти поля. Управляющий процесс формирует конфиг, а runtime API меняет скорости без рестарта.

```json
{
  "policy": {
    "requireSubscription": true,
    "subscriptions": {
      "account-123": {
        "emails": ["account-123-vless", "account-123-trojan"],
        "uplinkBps": 1250000,
        "downlinkBps": 6250000,
        "revision": 1,
        "disabled": false
      }
    }
  }
}
```

Добавляйте subscriptions в существующий policy, сохраняя levels/system. Это фрагмент, не полный серверный конфиг.

- account-123 — стабильный ID подписки backend; emails — серверные учётные идентичности Xray. Регистр нормализуется как в VLESS/Trojan; повтор email между/внутри групп отклоняется. ID не пустой, без краевых пробелов, до 1024 байт.
- Все email одной группы делят один бюджет направления внутри данного экземпляра Xray. Число соединений, профилей и IP не умножает лимит. Между нодами скорость не синхронизируется.
- Bps — **байты/с**. Мбит/с × 1 000 000 / 8. Пример: upload клиента 10 Мбит/с, download 50 Мбит/с. Если нужны «100 Мбит/с в каждую сторону», задайте оба значения 12500000: одновременно допустимы 100 up и 100 down. Общего up+down бюджета здесь нет.
- 0 — unlimited для направления. disabled=true отдельно запрещает передачу в обе стороны.
- revision по умолчанию 1; сохранённую ревизию восстанавливают из JSON при запуске.
- requireSubscription=true запрещает полезные данные аутентифицированным пользователям без привязки, включая пустой email. По умолчанию false для совместимости upstream: неизвестные email сохраняют прежнее поведение. Лабораторный сервер включает true.
- Максимум направления — 2^40 байт/с. Неверная стартовая конфигурация отклоняется.
- Учитываются полезные байты диспетчера. Заголовки, TLS/padding, повторы и расходы WebRTC-адаптера не равны этому счётчику.
- Начальный burst — 8192 байта. Runtime-обновления сохраняют объект и остаток credit, будят ожидающие операции; повтор update не выдаёт новый burst. Перезапуск процесса начинает новый бюджет.
- UDP-пакеты сохраняются целиком, не разбиваются. Оплата большого пакета несколькими ожиданиями может дать короткий всплеск; это pacing средней полезной скорости, не жёсткий packet policing.
- Управляемые unlimited пользователи тоже имеют обёртки для последующего включения ограничения. Raw splice для этих потоков запрещён, Vision продолжает работать буферно. Влияние на CPU нужно измерить под своей нагрузкой.

Runtime API, обязательные поля, CAS/retry и сохранение настроек панелью описаны в [RUNTIME_API.md](RUNTIME_API.md). Изменение/создание email-привязок пока требует обновления стартового конфига и перезапуска. API не создаёт пользователей Xray.
